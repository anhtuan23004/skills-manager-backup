# Verification: Output Verification Process

Some design-agent native environments (such as Claude.ai Artifacts) have a built-in `fork_verifier_agent` that spawns a subagent to check iframe screenshots. Most agent environments (Claude Code / Codex / Cursor / Trae / etc.) do not have this built-in capability; doing it manually with Playwright covers the same verification scenarios.

## 🔴 Rule 0: verify your verification tool first

**Before trusting any rendering result, first confirm that the renderer itself can render correctly.** This rule ranks before all other verification,
because when the tool is not trustworthy, every later step is giving you a false green light.

Two real failures (2026-09, a PPTX delivery that used a client template):

- **Thumbnails generated by macOS `qlmanage -t` let through 4 bugs that cause text overlap**. It uses a simplified
  rendering path and handles line spacing far more leniently than real PowerPoint. Going through all 20 pages one by one, everything looked right, and the user
  opened it in WPS and saw text on top of text. **A thumbnail is not a render; do not use it as acceptance evidence.**
- **LibreOffice on macOS renders Chinese PPTX entirely as tofu blocks**, which for a while made people think the file was broken.

**How to tell whether it is the tool's problem or the product's problem: run a control experiment.**
Feed a **known-correct file of the same kind** to the same renderer. In the second case above, when the client's official template original
was fed to it for rendering, its Chinese likewise disappeared completely, which immediately established that it was an environment problem and not a problem with your file.
This step saves hours of troubleshooting in the wrong direction.

**Trust ranking (macOS)**:

| Tool | Trustworthy? |
|---|---|
| `qlmanage -t` thumbnails | ❌ Cannot be used as acceptance evidence |
| LibreOffice headless | ⚠️ Layout is trustworthy; fonts/Chinese may be lost entirely |
| Keynote + AppleScript PDF export | ✅ First choice for automation, a real layout engine |
| Opening in the target software itself (PowerPoint / WPS) | ✅ Final confirmation, review manually |

⚠️ **Do not use System Events to inject keystrokes** to drive the GUI to page through and screenshot; the keys will land in whatever window the user is currently
typing in. Either use AppleScript's document-level API (such as Keynote's `export`), or review manually.

**Add one more mechanical check that does not depend on any renderer**: character-by-character text comparison (source data vs product,
which must be exactly equal after `re.sub(r'\s+','')`) and per-page element count comparison. A renderer can fool the eye but cannot fool a count.

## Verification checklist

Every time after producing HTML, go through this checklist:

### 1. Browser rendering check (mandatory)

The most basic: **can the HTML open**? On macOS:

```bash
open -a "Google Chrome" "/path/to/your/design.html"
```

Or take a screenshot with Playwright (next section).

### 2. Console error check

The most common problem in HTML files is a JS error causing a white screen. Run it through Playwright:

```bash
python ~/.claude/skills/huashu-design/scripts/verify.py path/to/design.html
```

This script will:
1. Open the HTML in headless chromium
2. Save a screenshot to the project directory
3. Capture console errors
4. Report the status

See `scripts/verify.py` for details.

### 3. Multi-viewport check

For a responsive design, capture multiple viewports:

```bash
python verify.py design.html --viewports 1920x1080,1440x900,768x1024,375x667
```

### 4. Interaction check

Tweaks, animations, button toggles: a default static screenshot cannot see them. **It is recommended to have the user open the browser and click through it themselves**, or record the screen with Playwright:

```python
page.video.record('interaction.mp4')
```

### 5. Slide-by-slide check

For deck-type HTML, screenshot one by one:

```bash
python verify.py deck.html --slides 10  # screenshot the first 10 slides
```

This generates `deck-slide-01.png`, `deck-slide-02.png`... for quick browsing.

## Screenshot best practices

### Capture the full page

```python
page.screenshot(path='full.png', full_page=True)
```

### Capture the viewport

```python
page.screenshot(path='viewport.png')  # by default only captures the visible area
```

### Capture a specific element

```python
element = page.query_selector('.hero-section')
element.screenshot(path='hero.png')
```

### High-resolution screenshot

```python
page = browser.new_page(device_scale_factor=2)  # retina
```

### Wait for animations to finish before capturing

```python
page.wait_for_timeout(2000)  # wait 2 seconds for animations to settle
page.screenshot(...)
```

## Sending screenshots to the user

### Open local screenshots directly

```bash
open screenshot.png
```

The user will view them in their own Preview/Figma/VSCode/browser.

### Upload to an image host to share a link

If remote collaborators need to see it (for example on Slack/Feishu/WeChat), have the user upload the screenshot with their own image-hosting tool or MCP, get a permanent link, and paste it anywhere.

## When verification turns up errors

### White screen

There must be an error in the console. Check first:

1. Is the integrity hash on the React+Babel script tag correct (see `react-setup.md` [not included in this copy])
2. Is there a `const styles = {...}` naming conflict
3. Are cross-file components exported to `window`
4. JSX syntax errors (babel.min.js does not report errors; switch to the non-minified babel.js)

### Choppy animation

- Record a trace with the Chrome DevTools Performance tab
- Look for layout thrashing (frequent reflows)
- For motion prefer `transform` and `opacity` (GPU accelerated)

### Wrong fonts

- Check whether the `@font-face` url is accessible
- Check the fallback fonts
- Chinese fonts load slowly: show the fallback first, then switch after loading finishes

### Layout misalignment

- Check whether `box-sizing: border-box` is applied globally
- Check the `*  margin: 0; padding: 0` reset
- Open the gridlines in Chrome DevTools to see the actual layout

## Verification = the designer's second pair of eyes

**Always go through it yourself.** When AI writes code, these often occur:

- Looks right but the interaction has bugs
- A static screenshot looks good but things misalign on scroll
- Looks good on a wide screen but breaks on a narrow one
- Dark mode was forgotten
- After toggling Tweaks, some components do not respond

**One last minute of verification can save an hour of rework**.

## Common verification script commands

```bash
# Basic: open + screenshot + capture errors
python verify.py design.html

# Multiple viewports
python verify.py design.html --viewports 1920x1080,375x667

# Multiple slides
python verify.py deck.html --slides 10

# Output to a specified directory
python verify.py design.html --output ./screenshots/

# headless=false, open a real browser for you to watch
python verify.py design.html --show
```

## Hard verification of video products (verify-video.sh) [not included in this copy]

Rendered MP4/finished videos are not passed by eyeballing; they are hard-verified with a script (verification on the HTML composition side is handled by the five-gate audit of `hyperframes check` [not included in this copy]; this script only covers the product side):

```bash
# Finished product (audio track required by default)
bash scripts/verify-video.sh final.mp4 --duration=22 --fps=60 --width=1920 --height=1080

# Silent intermediate product
bash scripts/verify-video.sh raw.mp4 --duration=10 --fps=60 --no-audio

# Cinematic style with a deliberate black-frame opening
bash scripts/verify-video.sh film.mp4 --duration=30 --fps=60 --allow-black-open
```

Checks: resolution/frame rate, duration error (±2%), presence of an audio stream (no audio track = machine enforcement of the "half-finished product" iron rule), black frames at start and end (blackdetect, a typical symptom of a recording start offset / loop jump-back), LUFS loudness (target for finished product -14±4). A non-zero exit code means it must not be delivered.
